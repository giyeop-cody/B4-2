# 이슈 #13: 폼과 삭제 대화상자의 접근성이 부족함

## 재현

- `label`에 `htmlFor`가 없어 글자와 입력칸의 관계가 코드에 분명하지 않았다.
- 오류와 로딩 영역에 알림 역할이 없었다.
- 삭제창은 일반 `div`라 화면 읽기 도구가 대화상자로 알기 어려웠다.
- 삭제창을 Escape 키로 닫을 수 없고, 삭제 중에도 다시 누를 수 있었다.

## 원인

마우스로 보이는 모양만 먼저 만들고 HTML의 의미와 키보드 동작을 확인하지 않았다.

## 해결

- 폼: `useId`, `htmlFor`, `aria-required`, `aria-invalid`, `aria-describedby`
- 오류: `role="alert"`
- 로딩: `role="status"`, `aria-live`
- 삭제창: `role="alertdialog"`, `aria-modal`, 제목 연결
- 삭제창이 열리면 취소 버튼에 초점
- Escape와 배경 클릭으로 닫기
- 삭제 중 버튼 잠금과 `aria-busy`
- 삭제 실패 시 창을 유지하고 내부에 오류 표시

## 선택과 한계

직접 간단한 초점 처리를 구현했다. 완성된 대화상자 라이브러리를 쓰면 초점 가두기까지 더 안전하지만,
이번 과제에서는 React 상태와 이벤트 흐름을 직접 배우는 것이 우선이라 작은 구현을 선택했다.
복잡한 서비스에서는 검증된 접근성 UI 라이브러리를 쓰는 편이 낫다.

## 재검사

- 대화상자 역할·초점·Escape·진행 상태 테스트 3개 추가
- 전체 테스트 14개 통과
- 제품 빌드 통과
