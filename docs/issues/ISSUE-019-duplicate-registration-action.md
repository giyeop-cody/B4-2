# 이슈 #19: 같은 등록 기능이 여러 UI에 중복됨

## 사용자 피드백

`등록`과 `새 아이템`은 모두 `/items/new`로 가는 같은 기능이므로, 의도한 것이 아니라면 둘 중 하나만 두어야 한다.

## 재현

목록 화면에서 다음 등록 동작이 함께 보일 수 있었다.

- 헤더의 `등록`
- 목록 상단의 `+ 새 아이템`
- 데이터가 없을 때 EmptyState의 `새 아이템 등록하기`

이름만 다르고 같은 주소로 이동하여 사용자가 기능 차이를 고민하게 만든다.

## 선택지

| 선택 | 장점 | 단점 |
|---|---|---|
| 헤더 `등록`만 유지 | 모든 페이지에서 바로 접근 | 목록의 대표 행동이 눈에 덜 띔 |
| 목록 버튼만 유지 | 목록과 새 항목 행동의 관계가 분명함 | 다른 페이지에서는 목록을 거쳐야 함 |
| 모두 유지 | 접근 위치가 많음 | 같은 기능이 중복되어 혼란 |

아이템 등록은 목록의 주요 행동이므로 목록 상단 버튼 하나를 선택했다.

## 수정

- 헤더의 `등록` 링크 제거
- 목록 버튼 이름을 `+ 새 아이템 등록`으로 명확하게 변경
- 빈 상태의 중복 등록 버튼 제거
- 필터 결과가 비어도 등록 링크가 정확히 1개인지 E2E 검사 추가

## 재검사

- 단위/컴포넌트 테스트 20개 통과
- 로컬 브라우저 테스트 2개 통과
- 제품 빌드 통과
