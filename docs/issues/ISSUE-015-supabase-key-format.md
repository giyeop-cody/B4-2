# 이슈 #15: 첫 원격 검사에서 Supabase 공개 키 형식을 잘못 가정함

## 발생

배포 번들의 공개 설정으로 원격 CRUD를 검사하려 했지만 “공개 anon key를 찾지 못했습니다”라는 메시지로 첫 검사가 실패했다.

## 원인

검사 도구가 Supabase의 예전 JWT 모양(`eyJ...`)만 공개 키라고 생각했다.
현재 배포는 새 `sb_publishable_...` 형식을 사용했다. 제품의 문제가 아니라 검사 방법의 가정이 오래된 것이었다.

## 해결

- 공개 키는 특정 글자 모양으로 판단하지 않고 환경변수 값 그대로 요청 헤더에 사용한다.
- 임시로 배포 설정을 확인할 때 새 publishable 형식을 인식하도록 고쳤다.
- 값 자체는 로그, 문서, 저장소에 출력하지 않았다.

## 재검사

새 공개 키 형식으로 원격 CRUD 네 단계와 Auth 설정 접근이 모두 통과했다.

## 배운 점

도구가 실패했다고 바로 서비스가 고장 났다고 결론 내리면 안 된다. 검사 도구의 전제도 확인해야 한다.
