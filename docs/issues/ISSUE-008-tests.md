# 이슈 #8: 자동 테스트와 `test` 명령이 없음

## 재현

기준선 `package.json`에는 `dev`, `build`, `preview`만 있고 `test`가 없었다.
화면을 눈으로 눌러보는 것만으로는 수정할 때 예전 기능이 깨졌는지 빨리 알기 어렵다.

## 선택

| 도구 | 장점 | 단점 |
|---|---|---|
| Vitest + Testing Library | Vite와 잘 맞고 사용자가 보는 문구·버튼으로 검사 가능 | 브라우저 전체 동작은 따로 검사해야 함 |
| 브라우저 E2E만 사용 | 실제 환경과 가까움 | 느리고 작은 실패의 원인을 찾기 어려움 |

먼저 작은 컴포넌트 규칙을 배우기 위해 Vitest와 Testing Library를 선택했다.

## 구현한 검사

- `StateView`: 로딩, 에러, 빈 데이터, 성공 4개
- `ItemForm`: 빈 필수값, 정상 제출값, 제출 중 버튼 3개
- 합계: 7개

## 설치 중 경고와 판단

Node.js 20에서 사용할 수 있는 jsdom 26을 설치할 때 하위 패키지 하나의 폐기 예정 경고가 나왔다.
최신 jsdom 30은 Node.js 22.22.2 이상이 필요하여 현재 배포 환경 범위를 넘어간다.
`npm audit` 결과는 취약점 0개이므로 지금은 jsdom 26을 유지하고 Node를 올릴 때 함께 갱신한다.

## 재검사

- `npm test`: 테스트 파일 2개, 테스트 7개 모두 통과
- `npm run build`: 다음 통합 검사에서 함께 확인
