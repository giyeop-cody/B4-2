# 추론 기록 #01: 프로젝트 구조 설계

## 질문: pages/components/hooks/lib로 폴더를 나눈 이유는?

### 설계 원칙: 관심사 분리 (Separation of Concerns)

React는 컴포넌트 기반 프레임워크이지만, 모든 코드를 한 곳에 두면 유지보수가 어렵다. 그래서 **역할에 따라 4개 폴더로 분리**했다.

### 폴더별 역할

| 폴더 | 역할 | 분리 기준 |
|------|------|-----------|
| `pages/` | 라우트 단위 — 각 파일이 하나의 URL에 대응 | URL = 페이지 = 파일 |
| `components/` | 재사용 단위 — 여러 페이지에서 공유하는 UI 조각 | 재사용성 + 단일 책임 |
| `hooks/` | 로직 단위 — 데이터 처리 로직을 UI에서 분리 | 관심사 분리 + 테스트 |
| `lib/` | 설정 단위 — 외부 서비스 클라이언트 및 유틸 | 인프라 계층 |

### 왜 이 구조인가?

**대안 1: 모든 컴포넌트를 한 폴더에**
- 파일이 20개 이상 되면 찾기 어렵고, 페이지 vs 재사용 컴포넌트 구분 안 됨
- 기각

**대안 2: feature 단위 폴더 (feature/items/, feature/auth/)**
- 기능이 하나뿐이라 오버엔지니어링
- 기각

**선택: 역할 기반 4폴더**
- 파일이 적어도 역할이 명확
- 새 페이지/컴포넌트/훅 추가 시 어디에 넣을지 고민 불필요
- 다른 CRUD 프로젝트에 그대로 재사용 가능

### 응용
- 기능이 늘어나면 `features/` 도입 고려 (예: features/items/, features/users/)
- 인증이 필요하면 `contexts/` 또는 `providers/` 추가
- API가 여러 개면 `lib/api/` 하위에 도메인별 파일 분리
